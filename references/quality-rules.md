# 质量检查规则 + 反 AI 腔清单

每次生成完内容,在交付给用户前过一遍这份清单。这是 Skill 输出和"普通 AI 输出"的根本差别。

---

## 一、字符数硬约束

### 单条推文字符上限

| 内容类型 | 英文上限 | 中文上限 |
|---------|---------|---------|
| 单推 Hot Take | 250 字符 | 130 字 |
| Thread 中段每条 | 240 字符 | 120 字 |
| Thread Hook(第 1 条) | 280 字符 | 140 字 |
| Thread CTA(最后 1 条) | 250 字符 | 125 字 |

**Hook 黄金长度**:英文 47-73 字符 / 中文 25-40 字
- 这是在 400 个账号上测试出来的最优区间
- 太短显得轻浮,太长读者不点"展开"

### 检查方法

生成完每条内容后,**在每条末尾标注 `[N 字符]` 或 `[N 字]`**,让用户一眼看到。

如果有任何一条超限,**直接重写**,不要交付超限版本。

---

## 二、AI 腔禁用词清单(绝对不要出现)

### 英文禁用词

**伪深度词**:
unlock, leverage, dive deep, delve into, robust, seamless, synergy, ecosystem, paradigm, journey, intricate, nuanced, multifaceted

**炫技转折词**:
moreover, furthermore, in conclusion, it's worth noting, let's explore, that being said, with that in mind

**过度形容词**:
game-changing, transformative, revolutionary, cutting-edge, groundbreaking, paradigm-shifting

**懒惰开场**:
"In today's fast-paced world..."
"In the realm of..."
"It's no secret that..."
"Have you ever wondered..."

### 中文禁用词

**互联网黑话**:
赋能、抓手、闭环、底层逻辑、链路、心智、范式、生态、维度、颗粒度、打法、势能、抓住红利、打透、跑通

**伪学术词**:
内卷、共识、心智模型、第一性原理(滥用时)、反脆弱、复利

**小红书腔(在 X 上更显 AI 味)**:
绝绝子、yyds、宝子们、姐妹们冲、爱了爱了、真的会谢、巨好用、神级、封神、宝藏

**懒惰开场**:
"今天想和大家分享..."
"作为一名 [身份],我想说..."
"在这个 [形容词] 的时代..."
"听我一句劝..."

**伪鸡汤收尾**:
"加油宝子们"
"愿你成为更好的自己"
"愿一切努力都被看见"
"希望对你有用"
"共勉"

### 检查方法

生成完后扫描全文,只要有上面任何一个词,**整段重写**。不要"替换一下"——一个词暴露的是整段的腔调问题。

## 三、结构检查清单

### 单推
- [ ] 总长度在限制内
- [ ] 三行以独立换行隔开,不连成一段
- [ ] 没有 hashtag(品牌活动除外)
- [ ] emoji 不超过 1 个
- [ ] 字符数留 30-50 余量

### Thread
- [ ] Hook 在 47-73 字符黄金区间(英文)
- [ ] Hook 单独成立,即使被 RT 也能看懂
- [ ] 中段每 3-4 条有配图建议
- [ ] 中段每条结尾有 Open Loop 钩子词
- [ ] 倒数第 2 条有"反方观点 / Bonus"
- [ ] 最后 1 条 CTA 不是 "Like and RT"

### 数据 Thread 额外检查
- [ ] 第 2 条有数据截图标记
- [ ] 每个具体数字精确到位(不是"很多""a lot")
- [ ] 包含 1 条"What didn't work"

### 案例拆解 Thread 额外检查
- [ ] 至少 3 个截图标记
- [ ] 包含"✅ Worth copying / ❌ Don't copy"对比段
- [ ] 包含"Counter-Take"反方段

### 反共识 Thread 额外检查
- [ ] **必须有"Where it breaks"段**(这是和"喷子内容"的本质区别)
- [ ] CTA 鼓励反驳,不是要赞同

## 四、CTA 模式速查

### ✘ 业余 CTA(不要写)
- "Like and RT if you found this helpful"
- "Drop a 🔥 if this resonated"
- "Comment 'GROWTH' for the full guide"
- "DM me 'PLAYBOOK' for free template"
- "求关注!"
- "希望对你有用,加油宝子们"
- "想要完整版资料的扣 1"

### ✓ 高水准 CTA

**Callback 闭环型**:
```
[引用第 1 条 Hook 的某个元素] + [低门槛订阅入口]

例: "Three years ago I had $8 in my account.
Now I write about scaling solo businesses every week.
If this resonated: @yourhandle"
```

**资源延伸型**:
```
"I document the full journey at [newsletter/blog].
Free, no upsell."
```

**反问诱发型**(反共识 / 清单 Thread 适用):
```
"Tell me where I'm wrong. Genuinely curious."
"And — what would you add to this list?"
```

**沉默型**(高级用法):
```
最后一条直接是一句金句,不带任何 CTA。
让读者自己决定是否关注。
适合个人 IP 已经有一定知名度的账号。
```

## 五、配图建议规则

### 必须配图的位置

| Thread 类型 | 必配位置 |
|------------|---------|
| 故事 Thread | 第 2-3 条(场景图)、第 5-6 条(数据/对话截图)、第 9-10 条(转折点) |
| 清单 Thread | 每 3 条 1 张工具截图 |
| 案例拆解 Thread | 第 3-4 条产品截图、第 5-8 条素材截图、第 9 条对比图 |
| 数据 Thread | 第 2 条总数据截图、每 2 条 1 张数据图 |
| 反共识 Thread | 第 3 条(数据论据处)、第 5 条(逻辑图) |

### 配图建议格式
```
📷 配图建议: [具体描述]
推荐素材: [实拍截图 / 数据图 / 对比图 / 流程图 / 无需配图]
```

### 配图原则
- **优先实拍/真实截图**,而不是库存图
- 不建议配 unsplash / pexels 那种唯美库存图(会显得是营销号)
- 数据截图如果隐私敏感,提示用户"打码后再用"
- 单推一般不配图,除非内容本身是"展示型"(对比、数据)

## 六、二次创作建议(发布后 4-6 小时)

每次交付完内容,告诉用户:

```
━━━━━━━━━━━━━━━━━━━
📌 二次创作建议
━━━━━━━━━━━━━━━━━━━

发布 4-6 小时后,可以引用转发自己,加一个更尖锐的观点。
这能让原推文的传播翻倍。

引用建议:
[Skill 自动生成 1-2 条引用转发的文案]
```

引用转发的文案应该是:
- 比原推更尖锐的观点(进一步推论)
- 或针对预期评论的回应
- 长度 < 100 字符 / 50 字

例:
```
原推: "做品牌的本质是占领一个具体动词"

引用转发(4 小时后): 
"补充一点:
99% 的品牌死在'我们要占领消费者心智'这种空话上。
真问题是:消费者用一个什么动词就想到你?
没有答案 = 没有品牌。"
```

## 七、发推时机建议

可选附加产出。如果用户问或者你判断他想知道:

| 时段 | 适用 |
|------|------|
| 工作日早 8-10 点 (US时区) | 数据 Thread / 干货清单 |
| 工作日晚 7-9 点 (US时区) | 故事 Thread / 反共识 Thread |
| 周末早 9-11 点 | 案例拆解 / 长内容 |
| 周末下午 | **不建议发**(互动率低) |

中文创作者面向中文受众,改为:
| 时段 | 适用 |
|------|------|
| 工作日早 8-9 点 | 通勤时段,适合短内容 |
| 工作日午 12-13 点 | 午休时段,适合 Thread |
| 工作日晚 21-23 点 | 黄金时段,适合长内容 |

## 八、最终交付前的自检流程

每次交付内容前,按这个顺序检查:

```
1. 字符数 → 全部在限内?
2. 禁用词 → 全文扫描?
3. Hook → 47-73 字符?能独立成立?
4. Open Loop → 每条结尾有钩子?
5. 配图 → 必配位置都标注?
6. CTA → 不是"Like and RT"?
7. 反方观点 → 反共识 Thread 有 Where It Breaks?
8. 二次创作建议 → 已附上?
```

**任何一项不过,重写,不要交付**。

## 九、特殊场景处理

### 用户的素材包含敏感信息(客户名、内部数据)
- 在配图建议里提示"打码后使用"
- 在内容里把具体客户名替换为"a Series A SaaS founder"或"某 DTC 品牌"
- 提醒用户:发布前再次检查是否泄露 NDA 范围内信息

### 用户素材有事实问题(数字夸张、时间线对不上)
- 不要纠正,但要追问:"这个数字是确切的吗?如果是大概,我们改成区间会更可信"
- 不要替用户编造数字

### 用户希望内容更"接地气"或更"装逼"
- 接地气:多用具体场景词("凌晨 3 点改方案"而不是"长期高强度工作")
- 装逼:可以保留少量行业 jargon,但**绝不能用禁用词清单里的**——那些是 AI 腔不是装逼

### 用户希望模仿某个特定大号的语气
- 让用户提供 3-5 条该账号的代表作
- 在生成时分析其特征(句长、标点、节奏、用词偏好)
- 严格按特征生成,不要混入"通用 X 文案腔"
