# X / Twitter 商业内容模板库

6 个模板,覆盖商业内容在 X 上的所有主流形态。每个模板包含:
- 适用场景
- 详细结构
- 中英文示例
- 反 AI 腔约束

---

## 模板 1:单推 Hot Take

### 适用
- 金句、暴论、短观点(类型 A)
- 有结论但缺乏支撑细节的反共识(类型 F 简版)
- 长 Thread 发布后 4-6 小时的引用转发

### 结构

**总长度**:英文 250 字符以内、中文 130 字以内

**三选一公式**:

#### 公式 A — 反共识三段式
```
第 1 行: [颠覆主流认知的结论 - 一句话]

第 2 行: [扎一刀的具体后果或证据]

第 3 行: [让人想反驳/想点赞的尖锐表达]
```

#### 公式 B — 数字反差
```
第 1 行: [具体数字 + 反预期结果]

第 2 行: [一句话解释为什么]

第 3 行: [可迁移的认知 - 一句话]
```

#### 公式 C — 身份 + 暴论
```
第 1 行: [身份] + [业内人不敢公开说的话]

第 2 行: [一个具体例子证明它真实]

第 3 行: [让读者自己得出结论的开放表达]
```

### 中文示例

```
别再迷信"做产品就会有人买"了。

真正赚钱的逻辑很简单:用软文铺满每一个流量平台,让用户在哪刷都看到你。

所谓"产品力",一半是产品,一半是密度。
```

### 英文示例

```
Stop pretending "build it and they will come" works.

Real revenue comes from carpet-bombing every traffic platform with content until users can't avoid you.

"Product-market fit" is half product, half density.
```

### 硬性要求

- 每行用空行隔开
- 不用 hashtag(品牌活动除外)
- 不用 emoji,或最多 1 个
- 直接陈述,绝不"I want to share..."
- 字符数预算留 30-50,给读者复制 + 引用空间

## 模板 2:故事型 Thread

### 适用
- 有完整时间线和细节的经历(类型 B 厚素材)
- 涨粉效果最强的类型

### 结构

**长度**:8-12 条
**单条字符**:英文 200 以内 / 中文 100 以内

#### 第 1 条 - Hook(决定 95% 命运)

三选一公式:

```
公式 1 - 时间 + 反差结果:
"In 2022, I was broke. By 2024, I'd built a $3M business. 
Here's the playbook (and the parts no one tells you):"

公式 2 - 数字 + 教训:
"I lost a $200K client last month. 
It was the best thing that happened to my business this year.
Here's why:"

公式 3 - 反共识承诺:
"Everyone says you need a niche to grow. 
I built to 50K followers without one. 
Here's how:"
```

中文版:
```
公式 1: 2022 年,我账户里只有 8 块钱。今年 1 月,我的咨询业务做到了 50 万 / 月。这是我做对的事(和踩过的坑):

公式 2: 上个月我丢了一个年费 200 万的客户。这是这一年发生在我身上最好的事。原因:

公式 3: 大家都说做内容必须先定位垂直领域。我没定位,做到了 5 万粉。怎么做的:
```

#### 第 2-3 条 - Setup
```
建立场景。具体到时间、地点、当时处境。
不抒情,只说事实。
```

例:
```
March 14, 9:47 PM. 
Client email: "We're going in a different direction."
$200K/year contract. Gone.
```

#### 第 4-9 条 - Value Delivery

每条只讲一个点,每条结尾留 Open Loop:

```
第 4 条: [事实/动作 1]
       [...]
       But here's what I didn't expect: ↓

第 5 条: [事实/动作 2]
       [...]
       And then this happened: ↓

第 6 条: [事实/动作 3]
       [...]
       The real lesson came next: ↓
```

每 3 条插入图片标记。

#### 第 10-11 条 - Lesson
```
1-2 个可迁移的认知。
不要"to recap"或"总结一下"。
直接给出让读者觉得"原来如此"的判断。
```

#### 最后 1 条 - CTA
```
✘ "Like and RT if helpful"
✘ "希望对你有用"

✓ Callback 引用第 1 条 Hook
✓ 给低门槛下一步

例:
"Three years ago I had $8 in my account. 
Now I write about scaling solo businesses every week.
If this resonated, more here: @yourhandle"
```

### 配图建议
- 第 2-3 条 Setup 处:1 张氛围/场景图(对话截图最佳)
- 第 5-6 条:1 张数据截图(Stripe / 后台 / 邮件)
- 第 9-10 条:1 张转折点截图(合同/签约图/客户邮件)

## 模板 3:清单型 Thread

### 适用
- 工具/资源/原则的并列展开(类型 C)
- 收藏率最高、长尾流量最强的类型

### 结构

**长度**:N+3 条(N 是清单项数,推荐 5-9)

#### 第 1 条 - Hook + Promise

```
公式: [具体投入] + [具体身份] + [Promise]

英文模板:
"I've spent [time/$$] testing every [category] tool out there.

These [N] are the only ones I still use:

(bookmarkable)"

中文模板:
"做 [领域] 这 [N] 年,我用过几乎所有 [类别] 工具。

这 [M] 个是我留到现在的:"
```

避免:
- 强行写 "thread 🧵"——已被滥用
- 第 1 条不能脱离上下文独立存在

#### 第 2 条 - Setup
```
两行:
- 建立筛选标准("用过 6 个月以上 / 都不是赞助 / 包括我抛弃过的")
- 给读者"留下来值得"的承诺
```

#### 第 3 至 N+2 条 - Each Item

每条结构必须四件事:
```
1. [工具名,Unicode 加粗 𝗧𝗼𝗼𝗹] + 一句话定位

2. [具体使用场景:"I use it when..."]

3. [一个非套话的细节,让人觉得"这哥们真用过"]

4. [一个小缺点 / "不适合谁用"]
```

不要编号,不要写 "Tool 1, Tool 2"——会让读者觉得后面还有很多懒得看完。

#### 倒数第 2 条 - Bonus
```
"Bonus: [一个意外的、稍微违反常识的工具或原则]"

这条往往是分享率最高的一条。
```

#### 最后 1 条 - CTA
```
"I write about [垂直话题] every [频率].
Follow @yourhandle if useful.
And — what would you add to this list?"

最后那个反问极其重要——评论区的工具补充会变成第二轮病毒源。
```

### 配图建议
- 每 3 条插一张工具截图(实拍,不要官方海报)
- 数据型工具放数据截图(收入/流量/订阅曲线)
- Bonus 那条建议配一张"这工具用法"的反直觉截图

## 模板 4:案例拆解 Thread

### 适用
- 分析他人公司、产品、打法(类型 E)
- 建立专业权威最快的方式

### 结构

**长度**:10-14 条

#### 第 1 条 - Hook
```
公式: [对象] + [反预期数据] + [拆解承诺]

英文示例:
"Notion grew to $10B without a single TV ad. 
I spent a week reverse-engineering exactly how. 
The playbook:"

中文示例:
"lululemon 在小红书 0 投放,自然流量做到品类第一。
我花了一周拆解他们到底做了什么。打法如下:"
```

#### 第 2 条 - Why You Should Care
```
告诉读者这个案例为什么和他们有关——他们能从中抄走什么。
```

#### 第 3-4 条 - 现象层(Surface)
```
描述他们做了什么——只描述事实,不解释。
用截图或数据让读者自己看到。
```

#### 第 5-8 条 - 结构层(Structure)
```
每条解构一个动作背后的商业逻辑。
关键:每条都要回答"为什么这样做行得通",而不仅是"他们做了什么"。
这是拆解和搬运的根本区别。
```

#### 第 9-10 条 - 借鉴层(Borrow)
```
✅ Worth copying: 可以抄的部分(具体到怎么抄)
❌ Don't copy: 不能抄的部分(为什么)

主动指出局限性会让两边的读者都参与讨论,这是病毒传播的关键。
```

#### 第 11 条 - 反方观点(Counter-Take)
```
"But here's what nobody talks about:"
点出这个案例的隐性代价或不可复制性。
```

#### 第 12-13 条 - Takeaway
```
2-3 句话,提炼出可迁移到读者业务的判断。
```

#### 最后 1 条 - CTA
```
"I tear down a different business every week.
@yourhandle if you want more of these."
```

### 配图建议(必须配,这是案例拆解的命门)
- 第 3-4 条:产品页截图 / 定价页截图
- 第 5-8 条:广告素材 / 落地页 / 运营截图
- 第 9 条:对比图(他们 vs 同行)
- **没有截图的拆解 = 二手内容,会被识破**

## 模板 5:数据 Thread

### 适用
- 有具体数字、转化率、金额的复盘(类型 D)
- 最直接的引流武器

### 结构

**长度**:8-10 条

#### 第 1 条 - Hook(必须含数字)

```
英文示例:
"From $0 to $50K MRR in 14 months. 
No funding. No team. 
Here's everything I did (and what I'd do differently):"

"I tested 47 cold email subject lines. 
3 got over 60% open rates. 
Here they are (with the data):"

中文示例:
"14 个月,从 0 做到 50 万 MRR。
没融资,没团队。
这是我做的全部 + 复盘的坑:"

"测试了 47 个客户开场白。
3 个让开口率超过 60%。
具体话术 + 数据:"
```

**铁律**:必须是具体数字,不能是"a lot"或"很多"。模糊数字 = 没人信。

#### 第 2 条 - Credibility / 可信度锚
```
一张数据截图(Stripe / Google Analytics / 银行流水打码版)。
没有截图就放具体到小数点的数字。
```

#### 第 3-7 条 - The What
```
每条讲一个具体动作 + 它带来的具体数字变化。

公式: [Action] → [Specific Number Change]

英文例:
"I switched from 30-min to 60-min calls. 
Conversion: 18% → 41%."

中文例:
"把咨询时长从 30 分钟改到 60 分钟。
成交率从 18% 升到 41%。"
```

#### 第 8 条 - What Didn't Work
```
公开列出 2-3 件失败的尝试。
这一条能让整篇 Thread 的可信度翻倍。
```

#### 第 9 条 - What I'd Do Differently
```
后见之明的一两条建议。
```

#### 最后 1 条 - CTA
```
✘ "DM me 'GROWTH' for the full playbook"——这种钓鱼式 CTA 现在被嘲讽

✓ "I document the full journey at [newsletter/blog].
   Free, no upsell."
```

### 配图建议(必须配)
- 第 2 条:总数据截图(MRR / GMV / 增长曲线)
- 第 3-7 条:每 2 条至少 1 张数据对比图
- 关键:**绝不能只有文字数字,必须有真实截图**

## 模板 6:反共识 Thread

### 适用
- 反主流共识 + 有 3 个支撑论据(类型 F 厚)
- 涨粉最猛但最难写的类型

### 结构

**长度**:8-10 条

#### 第 1 条 - Hook
```
直接放结论,不绕。

英文:
"Hot take: Most 'productivity advice' is procrastination dressed up. 
The 5 worst offenders:"

"Unpopular opinion: Most B2B SaaS startups should kill their content marketing. 
Here's the math:"

中文:
"一个不太正确但真实的观察:
大部分'生产力建议'都是变相拖延。
最坑的 5 种:"

"暴论:大部分 B2B SaaS 应该停掉内容营销。
我算了一笔账:"
```

#### 第 2 条 - Acknowledge
```
"I know this sounds crazy. Hear me out."
"我知道这听起来很反共识。但听我说完。"

然后承诺接下来要给的论据。
```

#### 第 3-5 条 - Three Arguments
```
每条一个具体论据:
- 一个数据
- 一个反例
- 一个底层逻辑

每条必须可独立成立,禁止"as I mentioned earlier"。
```

#### 第 6-7 条 - Where It Breaks(关键!)
```
"But here's where my argument breaks down:"
"但要承认这个观点不适用的场景:"

主动给出这个观点不适用的场景。
真正能病毒传播的反共识不是哗众取宠,而是有思考。
双方都参与才形成讨论密度。
```

#### 第 8 条 - Refined Conclusion
```
经过自己反驳后,重新表达一遍核心观点——这次更精确。
```

#### 最后 1 条 - CTA
```
"Tell me where I'm wrong. Genuinely curious."
"告诉我哪里不对,我想听反方观点。"

开放式收尾,鼓励反驳。
反对意见 = 评论区数据 = 算法推送 = 涨粉。
```

### 配图建议
- 第 3 条数据论据:数据图表
- 第 5 条逻辑论据:对比图或框架图
- 第 6 条:无需配图,文字本身有冲击力

## 跨模板通用元素

### Hook 黄金长度
**英文 47-73 字符之间**(在 400 个账号上测试出来的最优区间)。
中文按比例约 25-40 字。

### Open Loop(钩子词库)

英文:
- But here's what I didn't expect:
- And then this happened:
- The real lesson came next:
- Here's where it gets interesting:
- But that's not the surprising part:

中文:
- 但接下来发生的事让我意外:
- 真正的转折在下面:
- 但有意思的不是这个:
- 真正让我重新思考的是这个:

### Unicode 加粗(代替 markdown)
X 不支持 markdown,但支持 Unicode 加粗:
- **Bold** → 𝗕𝗼𝗹𝗱
- 仅在工具名、人名、关键概念时使用
- 滥用会让推文显得"做作"

可在生成时直接用 Unicode 字符,或在产出后告诉用户"建议把 X、Y、Z 改成 Unicode 加粗"。
